# F3a product grounding — one next usable slice

Implement one NEW operator-admitted synthetic exhibition profile, with a native
pre-activity offer, two separately bound player consent calls, ordinary issued
opposed action packets, explicit participant settlement, recipient retrieval,
and a later separate cooperative repair activity. Preserve D6/F1 admission and
old no-award practice unchanged. This is a source-grounded proposed contract,
not product/native/world qualification or an adopted authored fixture.

Current product source is `product28-build/package` (0.5.3.dev28), with its actual
engine lock still native16. The inspected successor source is
`f3a-root-integration-r2/engine` (native18); it is NOT current product authority.
At commissioning, root reported native17 API37PASS followed by independent
5FAIL/1PASS and a native18 narrow43-case run in progress. This report does not
reinterpret those results or transfer any media/native persistence evidence.
`sourceindex.json` pins exact read source bytes and AST/JSON sections. No source
or R1/R2 frozen directory was changed; no DB, Engine/Client/native API, test,
build, process job, Git, Library or remote action was performed.

## Recommended bounded product route

1. **Admit a new small authored profile.** Add an explicit
   `samsara-authored-exhibition/1` branch to the existing operator content
   preparation/activation boundary, keeping the D6 region schema unchanged.
   New records and contest/instance IDs are synthetic:f3a; the new exhibition
   definition is synthetic:f3a:exhibition:. Reuse strict parsing, native record
   validators, conflict/relational checks, immutable private carrier, source and
   compiled-spec pins, registry reload and bounded viewer disclosure. This is a
   concrete typed profile, not a generic participant-supplied namespace switch.
   It has exact existing-native anchor refs selected by the operator, or new
   explicitly admitted synthetic actors/site; it never silently teleports,
   equips, grants consent, regenerates quantities or edits existing F1 data.
   The profile must prohibit authored contest_terms/contest_consent/
   contest_settlement records and direct prize-resource deltas in exhibition
   actions: only the real native contest service produces those facts/awards.
   Initial new stock is explicit finite fixture data, not an outcome or consent.

2. **Open the offer before creating an activity.** An operator-only
   `contest.open` consumes the exact admitted definition/profile reference,
   chooses the explicit contest ID and captures current resource versions.
   Within the existing native UoW it starts one deterministic F3a-prefixed
   initial encounter and calls Contests.define. Return a scoped offer artifact
   and native terms reference. Before consent there are no activity_jobs,
   dispatcher requests, scene geometry, competitive costs or physical activity
   reservation. Native contest_terms and immutable product provenance artifacts
   own the offer; no second mutable award/consent ledger is introduced.

3. **Each player separately chooses.** `contest.inspect` discloses only native
   visible terms and accepted/declined/unresolved state. `contest.consent`
   accepts only contest reference and accepted/declined/withdrawn choice; actor
   and viewer come from the live authorized player context, never the payload.
   A worker/operator cannot answer for another entrant. Forward current CAS and
   immutable native request identity. Recheck presence/gear as disclosed
   admission conditions; native terms/consent remain the authority. Decline,
   withdrawal, ignoring an offer, leaving or doing ordinary work grants nothing
   and does not reserve or spend the opponent's afternoon. Changed source or
   resource pins require explicit new terms/offer, never amendment/refund.

4. **Begin only with both real native acceptances.** A bound entrant requests
   `contest.begin`. Check exact admitted profile, terms/consents, actual initial
   instance, current site/gear/resource pins and both actors' movement/physical
   availability in one UoW. Create one deterministic ordinary battle activity
   that reuses ONLY that proven operator-opened initial instance; do not call
   generic _start's new-instance route. This is a narrow internal verified
   offer-to-activity path, not a player-supplied encounter-ID attach bypass.
   Only now call existing _prepare/EncounterHandler and issue the first actual
   packet at the post-consent revision. Checkpoints/jobs remain ordinary;
   replay/begin duplicates cannot create a second episode.

5. **Play actual opposition through ordinary bound packets.** The new authored
   spec supplies at least one substantive choice/counterchoice for each actual
   entrant, with one unambiguous substantive actor per state and real native
   costs/geometry/counterplay. All history on an eligible route is kind:event;
   speech can be an actual authored dialogue_turn change within such an event.
   A real terminal effect leading to completed/achieved maps explicitly to a
   beneficiary role. Giving ground/evasion/withdrawal has its own non-award
   terminal path. Continue current presence/gear/reservation checks at commit.
   Keep participant cancellation/free exits available and accepted costs spent.
   For this new profile, require the bound current participant for decisions;
   operator maintenance ending remains separately labeled and never wins.

6. **Settle and retrieve separately.** `contest.settle` is an explicit bound
   entrant request after the actual terminal, not an automatic handler award.
   It passes no winner/amount/effects to native Contests.settle. In the same
   product UoW, project the real settlement/receipt/historical resource images
   into immutable participant-readable artifacts with entity/audience grants.
   Use a deterministic artifact key tied to the native settlement event and
   disclosed perspective. Return both normal artifact_ref and the explicitly
   typed native_reference inside its envelope. A second request/restart retry
   returns the same historical native fact without allocating again; spent
   current resources do not replace the historical proof. Actually retrieve
   those bytes as the recipient before claiming receipt/use.

7. **Offer a later, separately chosen repair.** The recipient's `contest.repair`
   consumes that exact retrieved settlement artifact and a pinned NEW repair
   definition, verifies native beneficiary/resource ownership/current pins,
   and starts a new life activity with parent_id:null: current _start forbids a
   child under a finished contest. Link by exact source_refs/native history,
   not by pretending the finished contest is still active. Author two explicit
   repair variants if either entrant may win, binding beneficiary/helper roles
   to the actual admitted people; expose only the eligible recipient's variant.
   The other entrant may separately accept help, decline, leave or ignore it.
   Use ordinary issued native event choices for that helper decision. An offer
   is not cooperation. Before actual helper acceptance creates owned geometry,
   this new profile must not reserve the unconsenting helper: use a narrowly
   verified new-profile reservation predicate over actual consent/owned live
   scene history, preserving old practice admission behavior. At acceptance,
   recheck both current actors/gear/scene availability, then reserve actual
   geometry. The recipient still separately chooses the material repair or
   stops; helper consent alone never spends the award.

The repair producer uses the existing Engine/Encounters path, with public native
`validate_conservation` over actual award/ incorporated-resource preimages and
semantic after allocations in the same UoW as dispatch, followed by checking the
actual historical transfer. Pin holder/unit/quantity/version, split target,
actual accessible tool/loadout and cooperative state. The authored material
event patches award1→0, incorporated0→1 and target split→repaired atomically;
refusal changes no material. The incorporated resource must have a legal
operator-selected site/character holder, with the exact target/resource linkage
pinned in the admitted repair contract and accepted receipt. It is not a new
award ledger. The whole new fixture's material accounting is pool2+award0+
incorporated0 →1+1+0 →1+0+1. General nonnegative quantity checks alone do not
prove this. No authentic F1 brace stock or old repair definition is repurposed.
