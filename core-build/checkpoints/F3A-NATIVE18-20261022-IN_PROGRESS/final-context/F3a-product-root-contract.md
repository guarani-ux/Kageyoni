`not_recovered_history:true` and `participant_authorlore:false`. IDs of this

`exhibition` has exactly `{id,version,spec,binding,site_id,ordinary_alternative}`.

`award` has exactly `{amount,unit,pool_id,destinations,eligible_actions,boundary}`.

Eligible actions must be actual authored terminal completed/achieved event
actions, mapped to a bound beneficiary role through the native terms validator.
Mere phase/done, actor testimony, evasion or maintenance end is not a winner.

`repairs` is a bounded list, exactly one variant for each possible beneficiary
role. Each has exactly `{encounter,beneficiary_role,helper_role,target_id,
target_loadout_id,award_id,incorporated_id,tool_id,tool_loadout_id,
material_action,helper_accept_action,helper_decline_action}`. `encounter` has
the exhibition fields above except a repair ID prefix and an ordinary-life
kind selected by root integration, not a recovery exemption. Both roles match
the profile binding; helper is distinct from beneficiary. Target/tool/loadouts
and incorporated resource are explicit new data or exact selected anchors,
never inferred ownership. Incorporated resource holder is a legal actual
character/location/faction, not an item ID. Pin its exact linkage to this target.
The material action is a native event that atomically decrements this award
resource, increments its incorporated counterpart and changes split→repaired.
No prize pool delta, unrelated target patch, other-holder transfer, fictional
healing, changed unit, fraction/bool or duplicate incorporation is allowed.
Helper acceptance/decline are actual separate actor choices, not an authoring
boolean or the exhibition's old consent. Neither offer nor acceptance alone
spends material. A real tool/loadout/current presence are checked at use.

For this first profile, entrant award resources and incorporated resources
start at zero. Material action requirements pin award quantity to amount,
incorporated quantity to zero and target condition to split; its exact quantity
patches are award→0 and incorporated→amount plus condition→repaired. Resource
unit/holder/version, tool access and genuine settlement are continuing runtime
guards, never inferred from those authoring requirements. Each beneficiary's
target/loadout/incorporated linkage must be unambiguous. No other repair action
or ending can patch prize/material resources or the repair target. Count every
resource in the fixture in later conservation observations, including unused
entrant/repair variants that remain zero.
