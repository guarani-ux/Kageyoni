## Pure image, not identity authentication

The first leaf is stdlib-only shape/transition validation. Namespace/profile is `samsara-source-authority/20261023-1`. A creation image has EXACT keys:

`profile, branch, workspace_id, source_id, controller_principal, recipient, source_payload_hash, source_metadata_hash, source_pin, artifact_pin, phase, revision`.

`profile` equals the literal above; `branch` is a nonempty controlled identifier (not hardcoded to main). `workspace_id, source_id, controller_principal, recipient` are nonempty strings with no leading/trailing whitespace or Unicode category C characters, at most512 UTF-8 bytes. Their shape does not establish authority, existence, binding, enrollment or consent. No participant may supply a controller identity to the product command later. `phase` is exactly active/withdrawn and revision is exactly int1/2, never bool or float. Active is revision1, withdrawn revision2. Creation validates active1 ONLY; inspection may validate either complete image.

`source_payload_hash, source_metadata_hash` are lowercase64-hex strings. They remain DISTINCT meanings even when accidental equal bytes occur: actual stored ingest payload hash, versus an independently computed immutable source-row metadata hash. The pure leaf accepts either well-shaped value; it cannot certify what bytes were hashed.

`source_pin, artifact_pin` are EXACT three-key dictionaries `id, version, digest`, with controlled identifier, exactly int version1 and lowercase64-hex digest. source_pin.id equals source_id. The source_pin digest is the actual source document-body digest; artifact_pin.id identifies the actual distinct native artifact; its digest must equal source_pin.digest because it holds those captured source bytes. artifact_pin.id MUST differ from source_id. No event ID, receipt, external controlRef or self hash belongs in this creation body. The real native pin exists after insertion, so requiring an existing controlRef before capture would be a bootstrap cycle.

Derive a control record ID with `source-authority:` plus SHA256 of UTF-8 canonical JSON `['samsara-source-authority/20261023-1', workspace_id, source_id]`, ensure_ascii=False/separators(',',':'). Pure deterministic ID is a routing name, NOT authentication or proof of actual native history.

Pure transition takes independently complete old/new images. It permits ONLY active1->withdrawn2 with every other field JSON/type-identical. Always refuse active->active, withdrawal->anything, revisions skipped, altered family/controller/recipient/pins/hashes/profile/branch. No updates or allocations are performed by this validator. Do not add caller-supplied winner/effect/outcome controls or a second mutable permission ledger.

The leaf exports a small explicit API: PROFILE, validate_image(value)->validated independent copy, validate_creation(value), validate_transition(old,new), authority_id(workspace_id,source_id).
