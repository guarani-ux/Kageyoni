# Source37 inquiry derivation: first producer boundary

Status: newly authored source-only foundation, not an installed Native interface.

The inspected current Native20 Documents.inquire method forms a payload with workspace_id, question, required_fields, claims, counters, viewer, and optional recipient. After authorization it currently refuses controlled-workspace derivation, before cached return or passage reads. Fresh execution reads every claims/counters evidence occurrence through _audience_passage. The result includes supports, counters and unavailable passages for every required field. Unavailable passages combine original claim and counter origins. document_inquiries stores mutable result_json and payload_hash; this producer currently creates NO output artifact and NO immutable typed derivation event. Those gaps must be implemented rather than inferred from existing rows.

The new pure inquiry_occurrences leaf accounts for all declared citation occurrences, including duplicates and unavailable passages, preserving original field/group/index. Its Counter keys use canonical JSON so bool/int selectors cannot compare equal accidentally. A trusted producer must subsequently resolve these selectors to actual stored family identity, source/artifact pins and any controls. This leaf does not resolve SQLite aliases, authenticate identities, validate passage text, establish current permissions or prove complete provenance of arbitrary free text. Question text remains caller-attributed input; a citation list cannot discover unreported external copying. Empty uncited results can be valid legacy inquiries and are not evidence of a controlled derivation.
