# Will ability development memo

User instruction: use the engine for all Kageyoni play. Resolve dictation against established identities and scene context. Never invent remembered canon or mechanics.

## Existing structure
The engine already has ability/capability plus will_definition, will_expression, will_technique, will_awakening, will_development and will_effect. JSON schemas live in schemas/will/. Extend these rather than build a duplicate system.

## Confirmed definition
Domain of the Painter is Sciel’s Will ability. Domains manifest physical space through Will. Within hers, Sciel perceives and temporarily affects underlying values of occupants, represented in the engine. Sebastian previously used an unbounded domain: the existing environment became his domain. This does not establish Sciel’s boundedness or automatic control of every value.

## Deferred implementation
Map this ability into existing Will contracts once the bearer expression and domain mechanics are established. Define spatial membership/boundaries, eligible stat visibility, target resistance, change limits and costs, duration, overlapping modifiers and safe expiration/restoration that preserves intervening changes. Do not invent numerical defaults. Determine whether a shared domain schema/registry extension is necessary; an all-ability catalog would index the existing schemas.

No domain activated. No stats altered. Current record is descriptive canon, not an executable technique. Campaign revision 5. Earlier partial-reconciliation limitations still apply.
