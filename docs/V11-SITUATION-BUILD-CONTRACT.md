# V11 Situation Build Contract

Status: active build contract.

## Objective
Complete the mechanical-trust gate, then implement and qualify the 22-slice Situation Architecture without creating parallel engines.

## Storage authority
- GitHub: engine source, migrations, tests, probes, Scar tooling, implementation docs, development history.
- Library: canonical campaign/world state, large artifacts, research corpus, evidence packages, release archives.

## Core distinctions
- Workspace: domain/runtime boundary.
- Situation Template: reusable required structure for a situation class.
- Situation: instantiated working world.
- Workflow: temporal/process structure.
- Frame: composition/view structure.
- Method: learned/adaptable participant technique.
- Domain Projection: participant-specific reorganization of attention/possibility within the shared Situation.

## Trust gate
1. No known mechanical trust scar remains reproducible.
2. Repair-derived attacks reveal no new material mechanical failure class after saturation.
3. Valid neighboring behavior continues to work.
4. Mutation tests exercise critical safeguards.
5. Inherited regressions remain green except reviewed version-contract changes.
6. Package source exactly matches qualified source.
7. Trust infrastructure does not silently alter canonical world state.
