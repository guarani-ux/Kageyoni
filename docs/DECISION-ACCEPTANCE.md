# Connected gameplay acceptance — before implementation

1. Proposals read actual character, knowledge, capability, equipment, property and story records. Exploration does not roll, charge costs or advance time.
2. Permission, probability, magnitude, cost, time and durable effects are distinct. Versioned rules and exact inputs are recorded; duplicate contributions and inconsistent units fail.
3. Explicit commitment pins a proposal. Stale state/definition edits fail. Retry/reload/interrupted commit preserve the same random result and do not double charge.
4. Character choice and other actors' responses remain separate. Missing mechanics/consent produce bounded judgment requirements, not invented permissions.
5. Will references are version checked, ownership checked and connected to the same outcome. Unsupported Will semantics explicitly require judgment rather than claiming fully automatic execution.
6. Outcomes, costs, decision history, time and supported process changes commit atomically. Mandatory unresolved work prevents advancement; reaction work remains discoverable.
7. Participant results do not reveal GM-only inputs. NPC judgments identify their own visible knowledge. Trusted GM APIs remain distinguished from authenticated user access.
8. Demonstrate a mixed travel/social/Will fixture: damaged bridge, independent family response, contextual stat advantage, fatigue/resource cost, timed environmental change, later route choices. Compare branch without repair.
9. Regressions, fresh creation, actual prior-save upgrade, interrupted commit, duplicate requests, wrong references, stale sessions, branch/replay/reopen and extracted package resume must pass.
10. Preserve original sources and campaign fiction. Deliver code, campaign, noncanonical fixture, commands, evidence, limitations and recovery instructions.
