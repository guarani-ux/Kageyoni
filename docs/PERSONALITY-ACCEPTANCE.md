# Personality integration acceptance — frozen before implementation

1. Reuse character aspects, knowledge, relationships, Will, properties, rules and the decision/event path. Add only explicit personality interpretations and dialogue turns as new domains. Migration creates no canonical personality assignments or story events.
2. Represent optional/provisional MBTI-inspired configurations, individual voice, mixed emotions, appraisals/thoughts, relationship-specific comfort, regulation, physical condition and time bounds. Unknown is not neutral or zero. Type does not determine morality, capability or Will.
3. Versioned authored policies deterministically weight alternatives from actual records and contexts. Weights are design likelihoods over the supplied options, not empirical psychological predictions or success bonuses. Same Will may accompany different personalities and expressions; no automatic Will grants or personality assignment.
4. Contextual tendencies feed dialogue, combat approach, relationships, discovery/options, decisions, practice and growth. Choosing a lower-weight option remains permitted; player consent, independent NPC responses and action mechanics remain separate.
5. Dialogue is grounded before drafting/commit. Persist speech separately from private grounding. Speaker knowledge, rumor/belief, observed information and world truth stay distinct. No automatic belief/trust change merely because a line is spoken. Annotated unknown claims require hypothesis/lie framing or explicit new evidence; literal prose semantics remain GM judgment.
6. Personality/affect/relationship changes can be consequences of decisions and can affect later recommendations. Stable habits do not decay merely because a chat message arrives. Temporal expiry changes active context while retaining history.
7. New interfaces enforce typed references, applicability, policy dependencies and scope; reject wrong types, invalid MBTI, missing/hidden source claims, duplicate influence IDs, invalid intervals, and inconsistent profile ownership.
8. Exact profiles/aspects/rule versions and judgments used are saved with decisions. Revision checks, retry idempotency, failed-commit rollback, branch isolation, snapshots, replay and reopened campaigns preserve them. Existing proposals survive upgrade with their supported old version fingerprints; newly unsupported/rescoped proposals require explicit reassessment.
9. Run the full baseline plus meaningful end-to-end scenarios: two same-type characters, two same-Will bearers, comfort/fear changing dialogue, refusal, personality-informed combat without a stat buff, learning/Will development without free mastery, hidden knowledge, and a later scene shaped by an earlier exchange.
10. Deliver campaign, fixture, code, generated schemas, migration, updated project workflows, requirement-to-evidence report, recovery instructions, and verified saved package. Installed skills and any unimplemented autonomous judgment must be reported accurately.
