# V4–V8 acceptance matrix

Frozen before the independent V4–V8 tests, 20 September 2026. Authority: implementation blueprint revision 2, including sections 16–22 and the V3 checkpoint. Baseline: 293 passing tests reported by root integration. This matrix states obligations; it does not report implementation success. All new fixtures are designed adversarial cases unless a reproduced defect is explicitly recorded.

No slice passes merely because its module imports, a receipt says completed, a critic approves it, or several named roles appear. Each row needs a valid positive control, its stated failure control and inspectable actual output. Existing coverage may satisfy a row when the integrated path still exercises that behavior.

## Executable comparison without paid model APIs

A useful minimum diagnostic uses a real project task: write a concise operator handoff from a frozen engine/source packet, preserving startup commands, supported operations, unknowns and recovery obligations. Freeze the packet, hard requirements and assessment rubric before generation. Compare a plain current-host response, a style-only configuration, one persistent method configuration, and a differentiated contribution/synthesis configuration using the same source facts and explicit output limit. Save each actual response, its source/configuration versions, available timing or execution counts, and checks against the frozen requirements.

Use the current authorized host or manual exchange; do not simulate a host call or substitute prewritten fixture text and call it a live comparison. Distinct roles or prompts are not independent experts. A single matched diagnostic can expose omissions, contribution use and overhead; it cannot establish general superiority or statistical reliability. The blueprint's suggested 32-run pilot remains separate unless actually executed. Creative usefulness and reader preference require an attributed judgment in addition to mechanical checks.

## Completion and reporting rule

Root owns final per-row receipts and integrated release verification. The independent review records actual failures before fixes and runs its focused tests against owning modules and real temporary files/databases. Unimplemented rows remain explicit gaps; they are not silently removed or redefined as complete. Broad claims about living intelligence, semantic correctness, professional competence or practical advantage require evidence beyond these deterministic acceptance fixtures.
